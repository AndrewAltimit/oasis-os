OASIS_OS is an embeddable operating system framework in Rust: window manager, browser engine, terminal, 15 apps and 17 skins — rendering to a 333 MHz PSP, a desktop window, a web page or an Unreal Engine 5 viewport. Hand it a framebuffer and an input stream; it brings the rest.

01 — What it is

A whole operating environment behind thirteen methods.

Not a UI toolkit: a complete shell — dashboard, windows, apps, a terminal, a browser — written once against a small set of backend traits. Core code never calls a platform API.

  1. 1

    Bring a surface

    A GPU window, a <canvas>, a game texture or a 2004 handheld’s framebuffer. Anything that can fill a rectangle and show a frame.

  2. 2

    Implement the contract

    SdiCore’s 13 required methods plus InputBackend::poll_events. One macro line fills in eight extension traits — 46 default methods for shapes, gradients, text, textures, clipping, vector paths, batching and render targets.

  3. 3

    Get the whole shell

    Windows, skins, the terminal, the browser and every app run unchanged on your surface — or skip Rust entirely and drive it from C through oasis-ffi.

// crates/oasis-types/src/backend/sdi_core.rs (doc comments trimmed)
pub trait SdiCore {
    fn init(&mut self, width: u32, height: u32) -> Result<()>;
    fn clear(&mut self, color: Color) -> Result<()>;
    fn blit(&mut self, tex: TextureId, x: i32, y: i32, w: u32, h: u32) -> Result<()>;
    fn fill_rect(&mut self, x: i32, y: i32, w: u32, h: u32, color: Color) -> Result<()>;
    fn draw_text(&mut self, text: &str, x: i32, y: i32, font_size: u16, color: Color)
    -> Result<()>;
    fn swap_buffers(&mut self) -> Result<()>;
    fn load_texture(&mut self, width: u32, height: u32, rgba_data: &[u8])
    -> Result<TextureId>;
    fn destroy_texture(&mut self, tex: TextureId) -> Result<()>;
    fn set_clip_rect(&mut self, x: i32, y: i32, w: u32, h: u32) -> Result<()>;
    fn reset_clip_rect(&mut self) -> Result<()>;
    fn measure_text(&self, text: &str, font_size: u16) -> u32;
    fn read_pixels(&self, x: i32, y: i32, w: u32, h: u32) -> Result<Vec<u8>>;
    fn shutdown(&mut self) -> Result<()>;

    // provided: override to report a resized window or a bound render target
    fn viewport_size(&self) -> (u32, u32) { ... }
}

// Implement those 13 for your type, then one line buys all eight extension traits:
oasis_types::impl_sdi_defaults!(MyBackend);
/* Any C-compatible host: link oasis_ffi (.dll / .so / .dylib) */
OasisInstance* os = oasis_create(480, 272, NULL, NULL, NULL);

while (running) {
    OasisInputEvent ev = {0};
    ev.event_type = OASIS_EVENT_BUTTON_PRESS;
    ev.key = OASIS_BUTTON_CONFIRM;
    oasis_send_input(os, &ev);

    oasis_tick(os, 1.0f / 60.0f);

    if (oasis_get_dirty(os)) {
        uint32_t w, h;
        const uint8_t* pixels = oasis_get_buffer(os, &w, &h);
        upload_texture(pixels, w, h);  /* RGBA, w*h*4 bytes */
    }
}

char* out = oasis_send_command(os, "ls /home");
oasis_free_string(out);
oasis_destroy(os);
// crates/oasis-app-core/examples/stopwatch_app.rs (excerpt)
impl App for StopwatchApp {
    // title, path, lines, layout, draw_windowed, drain_requests, ...
    impl_content_app_methods!(content);

    fn handle_input(&mut self, button: &Button, _vfs: &dyn Vfs) -> AppAction {
        match button {
            Button::Cancel => return AppAction::Exit,
            Button::Confirm => self.running = !self.running,
            Button::Square => self.laps.push(self.elapsed_ms),
            _ => return AppAction::None,
        }
        self.rebuild_lines();
        AppAction::None
    }

    fn tick(&mut self, dt_ms: u32, _vfs: &dyn Vfs) -> bool {
        if !self.running { return false; }
        let before = self.elapsed_ms / 100;
        self.elapsed_ms += u64::from(dt_ms);
        // redraw only when the displayed tenth changes
        self.elapsed_ms / 100 != before
    }
}

  • Embeddable by design

    Backends are leaf crates; the shell is a library you tick.

  • Skinnable to the bone

    Layout, chrome, strings and shaders are TOML; a theme derives from nine colors.

  • Actually useful inside

    A from-scratch browser, 110+ commands and builtins, video, radio — 15 apps.

  • Drivable by agents

    An opt-in, loopback-only MCP server opens apps, runs commands and takes screenshots.

02 — Platform targets

Same shell, five very different screens.

Each backend maps rendering, input, audio and networking onto whatever the host provides. Same apps, same skins, same terminal — from a 4K monitor to a 4.3″ LCD.

Desktop

oasis-backend-sdl → oasis-app

SDL3 window, renderer, input and audio on Linux, macOS and Windows. SDL3 builds from source; no system SDL needed. Skins pick their own resolution — the XP skin above runs at 1024×768.

    oasis-wm

    A real window manager

    Drag, resize, minimize, maximize, edge snapping with previews, Alt+Tab, five tiling layouts and open/close/minimize animations.

    oasis-mcp

    An MCP control server

    Compiled out unless asked for. When on: Streamable HTTP on 127.0.0.1:7345, Origin/Host checks, an optional bearer token, and tools like open_app, run_command and screenshot.

    oasis-terminal

    A shell inside the shell

    Pipes, globs, aliases, variables, if/while/for/case scripts, background jobs, tab completion and persistent history — and commands that drive the GUI.

    oasis-video · oasis-audio

    TV Guide & Internet Radio

    Internet Archive channels streamed progressively through a sliding-window buffer with deferred tail probing and CDN failover — decoded by ffmpeg, openh264, the browser, or the PSP’s Media Engine.

    oasis-ui

    27 widgets

    Buttons to tree views, modals, tables, date and color pickers — plus list views, menu bars, nine-patch, focus navigation and flex/grid layout.

    oasis-shader · -vector

    Living wallpapers

    Eight Shadertoy-style backgrounds, each with a GLSL and a CPU implementation, plus resolution-independent vector icons.

    oasis-vfs · oasis-net

    Files & wires

    Memory, disk and UE5 game-asset filesystems behind one trait; a PSK-authenticated remote terminal; and typed VFS IPC (/var/audio, /var/wm) that scripts, plugins and agents drive.

    06 — The PSP story

    Born on a 2004 handheld. Still runs there.

    OASIS_OS started in early 2026 as a love letter to PSP homebrew shells like PSIX. The 480×272 default resolution is the PSP’s LCD; the d-pad navigation never left. And the PSP is still the hardest target in the tree.

    CPU
    333 MHz
    RAM
    32 MB
    LCD
    480×272
    TLS
    1.3
    1. TLS 1.3 in pure Rust on firmware that ships SSL 3.0 and 2008-era root CAs.
    2. Hardware H.264 through a reverse-engineered Media Engine RPC protocol — 22 command IDs, 47 NIDs — with a kernel watchdog for a firmware deadlock.
    3. QuickJS-NG cross-compiled with pspdev’s toolchain against a hand-rolled libc shim.
    4. Zero-touch development: WiFi deploy, remote input and screen capture, a 154 KB recovery EBOOT, and a relay-driven actuator for hard reboots.

    08 — Getting started

    Build it for your screen.

    Per-platform dependencies live in docs/getting-started.md. CI runs every step inside the rust-ci Docker image, so a local docker compose --profile ci run matches it exactly. 

    # SDL3 compiles from source; default features link system ffmpeg
cargo build --release -p oasis-app
cargo run --release -p oasis-app

# pick any of the 17 skins
OASIS_SKIN=psix-hifi cargo run --release -p oasis-app

# run the tests
cargo test --workspace
    # no ffmpeg dev libs (e.g. Windows): openh264 + symphonia instead
cargo build --release -p oasis-app \
  --no-default-features --features javascript,video-decode

# leave out javascript for a build without QuickJS-NG
cargo build --release -p oasis-app --no-default-features --features video-decode

python3 -m http.server 8080
