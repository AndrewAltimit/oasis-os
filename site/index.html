OASIS_OS is an embeddable operating system framework in Rust: window manager, browser engine, terminal, 15 apps and 17 skins — rendering to a 333 MHz PSP, a desktop window, a web page or an Unreal Engine 5 viewport. Hand it a framebuffer and an input stream; it brings the rest.

01 — What it is

A whole operating environment that fits behind thirteen methods.

Not a UI toolkit: a complete shell — dashboard, windows, apps, a terminal, a browser — written once against a small set of backend traits.

A

Embeddable by design

Core code never calls a platform API. Implement SdiCore's 13 required methods plus input, and the entire shell runs on your surface — a GPU window, a canvas, a game texture or a 2004 handheld.

B

Skinnable to the bone

Layout, chrome, fonts, strings, wallpapers and shader backgrounds are data. Seventeen skins ship — from PSIX tributes to Windows XP — and a theme derives from just nine base colors.

C

Actually useful inside

A from-scratch HTML/CSS/Gemini browser, a scripting shell with 110+ commands and builtins, video and radio streaming, a text editor, paint, games and more — 15 apps.

D

Drivable by agents

An optional, loopback-only MCP server lets a local agent open apps, move windows, run commands and take screenshots — the shell as the interface for an on-device assistant.

02 — Platform targets

Same shell, five very different screens.

Backends are leaf crates. Each one maps rendering, input, audio and networking onto whatever the host provides — and the PSP gets two binaries of its own.

04 — Inside the shell

Subsystems built from scratch, then made small enough to travel.

oasis-browser · oasis-js

A browser engine, not a webview

Written from the parser up: a full CSS cascade — @media, @container, @layer, @supports, nesting and :has() — with var() resolved at computed-value time, 2D and 3D transforms with perspective, and @font-face web fonts.

  • preserve-3d
  • backface culling
  • bidi text
  • CSS transitions
  • CSP nonces & hashes
  • 8 MB body cap

oasis-wm

A real window manager

Drag, resize, minimize, maximize, edge snapping with previews, Alt+Tab, keyboard snapping, five tiling layouts and open/close/minimize animations.

oasis-terminal

A shell inside the shell

~95 commands and 20 builtins: pipes, globs, aliases, variables, $? exit status, if/while/for/case scripts, background jobs, tab completion and persistent history.

oasis-video · oasis-app-tv-guide

TV Guide & Internet Radio

Channels of Internet Archive video, streamed progressively through a sliding-window buffer with deferred tail probing and CDN failover — and decoded by ffmpeg, openh264, the browser, or the PSP's Media Engine.

oasis-ui

29 widgets

Buttons to tree views, modals, tables, date pickers and toasts — plus list views, menu bars, nine-patch, icon atlases and flex/grid layout.

oasis-mcp

MCP control server

Off by default, compiled out unless asked for. When on: Streamable HTTP on 127.0.0.1:7345, Origin/Host checks, optional bearer token, and tools like open_app, run_command, screenshot.

oasis-shader · oasis-vector

Living wallpapers

Shadertoy-style backgrounds — Voronoi, City Lights, Ocean Waves, Calm Waves, Balatro — on GPU or in software, plus resolution-independent vector icons and animations.

oasis-vfs · oasis-net

Files & wires

In-memory, on-disk and UE5 game-asset filesystems behind one trait; a PSK-authenticated remote terminal and FTP-style transfer; and typed VFS IPC (/var/audio, /var/radio, /var/wm) through which the terminal, plugins and agents drive the music player, radio and window manager.

06 — The PSP story

Born on a 2004 handheld. Still runs there.

OASIS_OS started in early 2026 as a love letter to PSP homebrew shells like PSIX. The 480×272 default resolution is the PSP's LCD; the d-pad navigation never left. And the PSP is still the hardest target in the tree:

  • TLS 1.3 in pure Rust on firmware that ships SSL 3.0 and 2008-era root CAs.
  • Hardware H.264 through a reverse-engineered Media Engine RPC protocol — 22 command IDs, 47 NIDs — with a kernel watchdog for a firmware deadlock.
  • QuickJS-NG cross-compiled with pspdev's toolchain against a hand-rolled libc shim.
  • Zero-touch development: WiFi deploy, remote input and screen capture, a 154 KB recovery EBOOT, and a relay-driven actuator for hard reboots.

08 — Getting started

Build it for your screen.

Per-platform dependencies live in docs/getting-started.md. CI runs every step inside the rust-ci Docker image, so a local docker compose --profile ci run matches it exactly. 

# SDL3 compiles from source; default features link system ffmpeg
cargo build --release -p oasis-app
cargo run --release -p oasis-app

# pick any of the 17 skins
OASIS_SKIN=psix-hifi cargo run --release -p oasis-app

# run the tests
cargo test --workspace
# no ffmpeg dev libs (e.g. Windows): openh264 + symphonia instead
cargo build --release -p oasis-app \
  --no-default-features --features javascript,video-decode

# leave out javascript for a build without QuickJS-NG
cargo build --release -p oasis-app --no-default-features --features video-decode
rustup target add wasm32-unknown-unknown
# needs wasm-pack: https://rustwasm.github.io/wasm-pack/installer/
./scripts/build-wasm.sh --release
python3 -m http.server 8080
# open http://localhost:8080/www/
# cargo-psp from the rust-psp fork, at the revision CI pins (RUST_PSP_REV)
cargo install --git https://github.com/AndrewAltimit/rust-psp \
  --rev <RUST_PSP_REV> cargo-psp --locked

# shell EBOOT
cd crates/oasis-backend-psp && RUST_PSP_BUILD_STD=1 cargo psp --release

# kernel-mode overlay PRX
cd ../oasis-plugin-psp && RUST_PSP_BUILD_STD=1 cargo psp --release
cargo build --profile release-ffi -p oasis-ffi
# add --features video-decode for the oasis_video_* API
# output: target/release-ffi/liboasis_ffi.so | liboasis_ffi.dylib | oasis_ffi.dll
# then: oasis_create() -> oasis_tick() -> oasis_get_buffer()
cargo build --release -p oasis-app --features mcp
OASIS_MCP=1 ./target/release/oasis-app
# agent config (.mcp.json):
# { "mcpServers": { "oasis": { "type": "http", "url": "http://127.0.0.1:7345/mcp" } } }
